# MediaLink 视频技能与技能包返回设计

日期：2026-09-01

状态：已通过（用户于 2026-09-01 确认）

## 1. 目标

在不改变现有生成协议、工作流注册、AutoDL 调度或素材落库流程的前提下，完成两项小范围改进：

1. 让分镜与视频生成技能保持模型无关，输出适合“一镜一条”的可执行视频提示词，并让提示词优化获得必要的媒体目标上下文。
2. 为独立的技能包管理窗口增加明确的“返回”按钮；点击后关闭该窗口，回到原有 MediaLink 设置窗口。

本次不运行真实图片、视频或云 GPU 工作流，不新增模型，也不硬编码 MiniMax H3、Seedance、ComfyUI 节点或供应商参数。

## 2. 保持不变的边界

- 继续使用统一 `generation_settings` 表单、实时 route schema 与单次确认凭证。
- 继续由服务端负责路由校验、后台执行、轮询、下载、落库和通知。
- 继续使用 `generate_media` / `generate_media_batch`，提交成功后结束当前 Agent run。
- 不允许 Agent 猜测或静默替换 route、模型、参数、参考素材、任务 ID 或工作流。
- 不更改工作流导入、云 GPU 实例、SSH、Keychain、调度、恢复和素材关联实现。
- `work/` 保持不修改、不暂存。

## 3. 视频与分镜技能

### 3.1 分镜写作

`storyboard-writer` 改为模型与供应商无关：

- 删除 Seedance 2.0、固定 15 秒、8K、HDR10+、120fps、固定伦勃朗光和固定体积光等全局硬编码。
- 默认采用“一镜一条”：每个可生成 section 对应一个独立镜头和一个后续生成任务。
- 每镜只承担一个主要叙事动作、一个主要运镜和一个清晰结束状态；复杂剧情拆成多个镜头，不在一条提示词里要求模型自行剪辑多个镜头。
- 时长、比例、分辨率、音频及模型专属参数由生成时所选 route schema 确认，不在分镜文档中伪造平台限制。
- 人物、场景、道具、时空、屏幕方向和动作承接继续从项目文档中复用，保持跨镜连续性。
- 分镜正文自然覆盖：主体与初始状态、动作随时间的发展、相机路径与速度、结束状态、光线与空间、连续性锚点、台词/声音，以及必要禁止项。
- 只有剧情需要时才使用慢动作、手持、体积光、浅景深等语言，不把它们作为每镜固定模板。

### 3.2 视频生成技能

保留现有安全和交易边界，删除与 MCP 工具说明重复的长篇字段协议，使技能集中在 Agent 决策：

- 锁定单个目标或批量范围。
- 从已有 section 和素材构造“一镜一条”的基础 prompt。
- 打开统一生成设置表单，原样使用用户确认的 route、params、参考素材、提示词补充和优化配置。
- 单项调用 `generate_media`，批量调用一次 `generate_media_batch`；一个镜头对应一个 batch item。
- 任务被接受后立即结束，不在同一 run 轮询、重试、换模型、选片或回写。

每个视频 prompt 至少明确：初始画面、主要动作、主要运镜、节奏、结束状态、连续性、音频/台词和禁止变化。已有首帧或参考图时，只描述需要发生的变化与必须保持的锚点，不重复重塑参考图中已经确定的外观。

批量流程顺序明确为：读取一次分镜 → 选择范围/是否试片 → 打开统一生成设置表单 → 提交单条试片或一个批次。试片完成后的正式批次必须在新 run 中重新确认设置。

### 3.3 可选择的提示词补充

内置视频提示词补充保持平台无关，不把 H3 写进核心技能。至少提供可复用的单镜电影叙事补充，约束一个主要动作、一个主要运镜、起止状态和连续性；产品展示环绕补充继续保留，但不得同时要求互相冲突的环绕与推近。

以后需要 H3、多图参考或某个 ComfyUI 工作流专用优化时，通过可编辑技能包/提示词库新增模板，由用户在统一表单中选择，不修改核心生成流程。

## 4. 提示词优化上下文

提示词优化仍由现有文本执行器完成，返回值仍是纯提示词正文。服务端在优化请求中补充最小、可验证的目标上下文：

- 目标媒体类型（本次为 video）。
- 已确认的目标模型名称（存在时）。
- 已确认的生成参数摘要。
- 参考素材数量。

优化指令要求：保留剧情事实、人物身份、台词、时空、首尾状态和用户明确风格；把视频内容组织成单镜时间过程；不添加新角色、新剧情、转场、镜头切换或未确认参数；发现输入中互相冲突的多个运镜或质量参数时，以单一主要动作和单一主要运镜为准。

不把内部确认 ID、文档 ID、资产 ID、路径、URL、通知目标或工作流 JSON发送给提示词模型。具体 route 参数仍由生成请求原样提交，优化器只改写 prompt 文本。

## 5. 技能包管理返回按钮

根因是 `/prompt-pack-editor` 被 `App` 作为独立界面渲染，并由 Electron 打开独立 `BrowserWindow`，因此不会继承设置页导航；编辑器自身标题栏也没有关闭入口。

在技能包管理标题左侧增加可访问的“返回”按钮：

- Electron 或脚本打开的浏览器弹窗：关闭当前技能包管理窗口，原 MediaLink 设置窗口保持不变并重新可见。
- 普通浏览器直接访问且窗口无法关闭：导航到 `/settings`，避免按钮无反应。
- 返回动作复用现有窗口关闭保护；本地草稿继续按现有草稿存储规则保留。
- 不新增 IPC，不在编辑器窗口内复制一套设置页，也不改变窗口尺寸和导航布局。

## 6. 错误处理

- 提示词优化上下文缺失模型或参数时省略该项，不猜测值。
- 无可用生成 route、参数无效或参考图不兼容时继续由统一表单阻止提交。
- 返回按钮关闭失败或当前窗口不可关闭时执行 `/settings` 回退，不展示第二套技能包编辑器。
- 生成提交失败时报告即时错误并停止，不自动重试或切换模型。

## 7. 测试与验收

采用测试先行：

- 内置技能测试先证明旧技能仍包含模型/参数硬编码，再修改为模型无关规则。
- 提示词优化单元测试验证 video 目标上下文、单镜约束、敏感内部字段不进入优化 prompt；图片或缺省场景保持兼容。
- 技能包编辑器组件测试先证明不存在“返回”按钮，再验证点击后优先关闭窗口、不可关闭时导航 `/settings`。
- 运行相关 Go、Vitest、lint/format、构建和 `git diff --check`。
- 打包后在 `/Applications/MediaLink.app` 实际确认返回按钮与 Codex 接入状态；不触发真实生成。

# MediaLink 参考素材拖拽导入设计

日期：2026-09-02

状态：已通过（用户于 2026-09-02 确认）

## 1. 目标

让用户可以把 Finder 中的视觉素材直接拖入图片或视频生成界面。除服务端内容识别与浏览器声明不一致的安全例外外，每个通过预检并成功上传的文件都必须：

1. 通过现有素材上传接口永久加入当前项目素材库，或在没有项目上下文时加入全局素材库；
2. 当前批次结束后立即成为当前生成请求的已选参考素材；
3. 重新打开对应素材库后仍可使用。

本次不建立临时引用、第二套文件存储或全窗口拖拽系统。

## 2. 交互范围

提供两个局部拖放入口：

- 生成面板的 composer 卡片；
- 参考素材选择弹窗的内容区域。

拖拽文件进入有效区域时，显示清晰遮罩和“松开以加入素材库并设为参考素材”。离开区域或取消拖拽时立即移除遮罩；完成投放后，遮罩切换为导入进度并在本批结束时移除。

不在应用窗口、文档编辑器或项目侧栏注册全局文件投放处理，以免影响文档、文件夹和其他素材的现有拖拽行为。

## 3. 数据流与复用边界

现有文件选择上传与新增拖拽入口共用一个小型批量导入核心。该核心负责：

1. 接收有稳定顺序的 `File[]`；
2. 按当前生成 route 的参考素材能力预检文件；
3. 对被接受的文件调用现有 `uploadMediaAsset(file, projectId)`；
4. 返回按原文件索引排列的逐项结果和上传成功的 `MediaAsset`；
5. 由调用方把成功素材乐观写入现有素材库缓存，再将其 ID 追加到当前 `referenceAssetIds`。

批量导入核心只封装分类、预检、有界并发、顺序和逐项结果，不拥有页面状态。生成工作台的 `useGenerationReferences` 与智能体统一生成设置的 `useGenerationSettingsForm` 分别负责把结果提交到各自现有状态；两边不复制文件分类或上传循环。`ReferenceSelectionDialog` 的文件按钮和拖拽均把 `File[]` 交给调用方，不再传递原始 input change event。

不复制 `uploadMediaAsset`，不绕过 MediaAsset 服务直接保存本地路径，也不让前端构造素材 ID。文件选择按钮开启 `multiple`，确保按钮上传与拖拽使用同一批量行为。

存在当前项目时，沿用现有上传接口把素材关联到当前项目。没有项目 ID 时，沿用现有 `/media-assets` 全局素材库行为；不得为拖拽单独创建隐式项目或不同归属规则。

## 4. 校验与数量规则

投放时使用当前 route 已声明的能力作为唯一依据：

- 只处理 `DataTransfer` 中真正的 `File`；内部卡片拖拽或其他没有 `Files` 类型的拖拽不拦截；
- 拒绝零字节文件；文件夹或无法取得 `File` 的项目视为无效投放；
- 首先按 `File.type` 的 `image/`、`video/`、`audio/` 前缀识别种类；MIME 为空时才按扩展名回退：图片为 `png/jpg/jpeg/webp/gif/bmp/avif`，视频为 `mp4/webm/mov/m4v`，音频为 `mp3/wav/m4a/aac/ogg/flac`；仍无法识别则不上传；
- 预检种类必须包含在 `referenceKindsForRoute(route)` 中；
- 计算当前已选数量和 route 允许的最大数量，只接受仍可立即选中的文件；
- 不支持参考素材的 route 不显示可用投放状态；
- 空投放、无法识别的文件和超出剩余名额的文件不上传；
- 上传成功后再用服务端返回的 `MediaAsset` 和现有 `canUseAssetAsReference` 做二次校验，防止浏览器声明与服务端内容识别不一致。二次校验失败的素材已经永久入库，但不选中、不自动删除，并明确提示“已入库但不兼容当前模型”。

数量超限时不采用“全部入库、只选一部分”的隐式行为。预检阶段被拒绝的文件保持未上传。只有上传后的服务端内容识别与预检种类不一致时，才允许出现“已入库但未选中”，并必须明确告诉用户。

作为同一契约修正，Codex 生图 route 在 catalog 中声明与 provider 一致的 `maxReferenceUrls: 10`。这不是新增 schema；只是消除 catalog 的“未声明上限”和 provider 的硬上限 10 之间的不一致。AutoDL 图片和 H3 继续使用各自已有的 route 上限，不统一改成 10。

## 5. 批量上传与状态

多文件按用户投放顺序编号，并以最多 2 个并发请求上传，避免瞬间发起大量请求。每个请求结束时只更新 `processed / total` 进度；整批 settle 后，才按原始文件索引一次性追加全部成功素材 ID。失败项跳过，因此选择顺序不会受网络完成顺序影响。

批次结果使用明确的逐项状态：`uploaded`、`uploaded_incompatible`、`rejected` 或 `failed`，并保留文件名、原始索引、可读原因和成功入库时的 `MediaAsset`。`total` 是本次取得的 `File` 数，预检拒绝项立即计入 `processed`，其余项目在请求结束时计入；界面显示“正在导入 2/5”。整批完成后显示一次成功选中、已入库但不兼容、预检拒绝和上传失败数量汇总。

成功素材先按 ID 乐观合并进当前 SWR 素材缓存，再触发后台 revalidate，随后提交选择 ID。这样即使刷新请求暂时失败，返回的素材对象和选择也不会被“缓存中不存在”副作用立即清除。`selectedReferenceAssets` 必须按 `selectedReferenceAssetIds` 的顺序映射素材，而不是按素材库数组顺序 `filter`。

拖入素材只改变素材库和参考素材选择，不自动开始图片或视频生成，不消耗生成额度。

## 6. 错误处理

- 投放前校验失败：不上传对应文件，并报告具体文件名和原因。
- 部分上传失败：保留已经成功入库并选中的素材，不回滚成功项；只列出失败项。
- 全部失败：保持原有参考素材选择不变，并显示可理解的错误信息。
- 上传期间再次投放：不启动重叠批次；界面明确显示当前导入仍在进行。
- 素材库 revalidate 失败但上传已成功：保留乐观缓存中的服务端素材对象、素材 ID 和当前选择，并提示素材列表刷新失败，允许之后重新加载。
- 组件卸载或用户离开页面：停止继续更新已卸载界面；已由服务端成功保存的素材仍保持永久入库。
- 上传开始时固定当前 route ID、剩余名额和原有选择作为该批次快照，并在批次进行中禁用新的文件投放。提交选择前若发现 route ID 已变化，成功素材仍永久入库，但本批不自动选中，并提示用户按新模型重新选择；不把旧 route 的判断结果套到新 route。

错误提示不得只显示 `internal error`；前端应在安全范围内保留服务端可读错误，未知错误使用统一兜底文案。

## 7. 组件职责

### `useGenerationReferences`

- 暴露可供文件输入和拖拽共同调用的批量导入动作；
- 统一执行能力、类型、数量、上传、缓存刷新、去重和顺序管理；
- 暴露上传中状态和批次结果；
- 保留现有素材选择、移除和 route 切换行为。

### `useGenerationSettingsForm`

- 使用同一个批量导入核心，让智能体弹出的统一生成设置表单也支持多文件选择和拖拽；
- 继续通过现有 `commitValue` 更新表单中的 `referenceAssetIds`，不引入第二个选择状态；
- 仍只接受该表单当前 route 支持的图片参考和数量；不借本功能扩展统一表单现有的参考种类范围。

### `GenerationComposerPanel`

- 整个内层 composer 卡片作为生成页的局部拖放目标，因此没有已有参考缩略图时也能投放；
- 只管理拖拽进入、离开、投放和视觉遮罩；
- 把文件交给 hook，不自行上传或修改素材 ID。
- 只有存在导入回调且当前 route 支持参考素材时才阻止外部文件投放；不影响内部 DOM 拖拽。

`GenerationWorkspace` 直接把导入动作传给该组件；新版 `MediaGenerationWorkspace` 经 `MediaGenerationInputPanel` 透传同一组 props。两条现有生成界面调用链都纳入验收，不能只修其中一个。

### `ReferenceSelectionDialog`

- 提供与生成面板一致的局部拖放体验；
- 整个弹窗内容区接受外部文件，文件选择按钮和拖拽都调用同一个批量导入动作；
- 上传成功后保持弹窗可用，并立即呈现新素材的选中状态。

上传进度显示在 composer 遮罩和弹窗工具栏已有上传位置；完成后的逐项失败汇总使用调用方现有错误区域，不新增全局通知系统。

不新增全局拖拽 provider、独立上传 store 或新的后端 API。

## 8. 测试与验收

采用测试先行，至少覆盖：

- 在支持图片参考的 route 中拖入一张图片：调用现有上传接口一次，乐观写入素材缓存并立即选中；
- 多文件上传即使乱序完成，最终选择顺序仍与投放顺序一致；
- 文件输入和拖拽共用同一处理逻辑，原上传按钮没有行为回归；
- 不兼容 MIME、未知扩展名、零字节、文件夹、空投放和不支持参考素材的 route 均不上传；
- MIME 为空但扩展名受支持的文件可以上传；服务端返回不兼容种类时只入库、不选中且明确报告；
- 当前已选数量与新文件合计超限时，超限项不上传并给出明确提示；
- 部分失败时成功项保留在素材库和已选列表，失败项可识别；
- 上传期间不接受重叠批次；
- 拖拽遮罩在进入、离开、取消和完成后状态正确；
- 内部 DOM 拖拽不会触发上传；
- 拖入素材不会触发生成 API；
- 有项目时重新加载项目后，可在项目素材库中找到成功上传的素材；无项目时可在全局素材库找到；
- 生成工作台、`MediaGenerationWorkspace` 和智能体统一生成设置表单三条入口行为一致；
- catalog 测试验证 Codex route 上限为 10，并与 provider 校验一致。

运行相关 Vitest、TypeScript、格式检查和 `git diff --check`。无需执行真实生图、视频生成或云 GPU 工作流。

## 9. 明确不做

- 不支持只在本次请求有效的临时文件引用；
- 不捕获整个 MediaLink 窗口的文件拖放；
- 不添加剪贴板粘贴、URL 抓取、文件夹递归导入或素材批量编辑；
- 不改变生成确认、路由 schema、素材存储格式或后端上传协议；
- 不在本规格中处理 Codex 生图结果导入、提示词优化超时或 MiniMax H3 提示词规则；这些是独立修复项，避免把多个子系统混入一次改动；
- 不修改、不暂存用户的 `work/` 目录。
